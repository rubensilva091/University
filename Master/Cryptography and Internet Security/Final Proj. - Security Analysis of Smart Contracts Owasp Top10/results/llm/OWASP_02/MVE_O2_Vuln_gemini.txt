### One-sentence summary of the most critical finding:
The contract is critically vulnerable to reentrancy in the `withdrawAll` function, allowing an attacker to drain all funds from the contract.

---

### Detailed Vulnerability Report:

#### 1. Vulnerability Type: Reentrancy
*   **Severity:** Critical
*   **Affected function and line number(s):** `withdrawAll`, lines 25-28
*   **Brief description of the risk:** The `withdrawAll` function first calculates the `amount` to be sent and then performs an external call `msg.sender.call{value: amount}("")` *before* resetting the user's balances (`deposits[msg.sender] = 0; bonusOf[msg.sender] = 0;`). A malicious contract acting as `msg.sender` can re-enter the `withdrawAll` function during the external call's execution, before the balances are zeroed, allowing it to withdraw the same funds multiple times. This can lead to a complete drain of all Ether held by the contract.
*   **Recommended fix:** Implement the Checks-Effects-Interactions pattern. Move the state updates (`deposits[msg.sender] = 0; bonusOf[msg.sender] = 0;`) to occur *before* the external call (`(bool ok, ) = msg.sender.call{value: amount}("");`). Alternatively, use a reentrancy guard like OpenZeppelin's `ReentrancyGuard` to prevent re-entrances.

#### 2. Vulnerability Type: Logic Error / Unbounded Operations / Asset Drain
*   **Severity:** High
*   **Affected function and line number(s):** `claimBonus`, line 15
*   **Brief description of the risk:** The `claimBonus` function allows any user with `deposits[msg.sender] >= 1 ether` to claim a `0.1 ether` bonus. Crucially, there is no mechanism to track if a bonus has already been claimed, allowing eligible users to call this function repeatedly to accumulate an arbitrary and unlimited amount of bonus funds. These accumulated bonuses can then be withdrawn, systematically draining the contract's Ether balance over time.
*   **Recommended fix:** Implement a mechanism to ensure that each user can only claim the bonus once. This could involve adding a mapping like `mapping(address => bool) public hasClaimedBonus;` and setting it to `true` after the first successful claim, and then adding a `require(!hasClaimedBonus[msg.sender], "bonus already claimed");` check.
