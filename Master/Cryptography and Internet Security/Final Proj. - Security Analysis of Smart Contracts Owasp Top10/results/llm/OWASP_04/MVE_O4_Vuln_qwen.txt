### Vulnerability 1: Flash Loan Attack on Bonus System  
1. **Vulnerability Type**: Flash Loan Exploit  
2. **Severity**: Critical  
3. **Affected Function**: `deposit()` (lines 12-15)  
4. **Description**:  
   The contract awards a 1 ETH bonus immediately if a user deposits ≥10 ETH. An attacker can exploit this by using a flash loan to temporarily deposit 10 ETH, claim the bonus, and repay the loan, effectively stealing 1 ETH for free. The bonus is granted without verifying that the user retains the principal after withdrawal.  
5. **Recommended Fix**:  
   Delay the bonus until the user has held the principal for a specific period or ensure the bonus is only claimable after the principal is withdrawn. Alternatively, tie the bonus to the principal balance at withdrawal time.  

---

### Vulnerability 2: Unprotected `fundPool` Function  
1. **Vulnerability Type**: Unrestricted ETH Inflow  
2. **Severity**: Medium  
3. **Affected Function**: `fundPool()` (line 7)  
4. **Description**:  
   The `fundPool` function allows anyone to send ETH to the contract without updating the `principal` mapping. This ETH is not tracked in user balances, creating a potential imbalance between the contract's actual balance and the tracked user balances.  
5. **Recommended Fix**:  
   Remove or restrict the `fundPool` function to prevent untracked ETH inflows. If necessary, ensure all incoming ETH updates user balances appropriately.  

---

### Vulnerability 3: Use of `call{}` for ETH Transfers  
1. **Vulnerability Type**: Potential Reentrancy (Mitigated)  
2. **Severity**: Low  
3. **Affected Function**: `withdrawAll()` (lines 23-25)  
4. **Description**:  
   The contract uses `call{}` to send ETH, which is generally vulnerable to reentrancy. However, the state (`principal` and `bonus`) is zeroed **before** the transfer, mitigating reentrancy risks. This is not a critical vulnerability but is a best practice issue.  
5. **Recommended Fix**:  
   Use `transfer()` or `send()` instead of `call{}` for safer ETH transfers, or ensure state updates occur **before** external calls.
