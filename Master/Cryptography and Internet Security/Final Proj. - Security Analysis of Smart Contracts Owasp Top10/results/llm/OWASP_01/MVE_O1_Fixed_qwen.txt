### Vulnerability Analysis

1. **Vulnerability Type**: Reentrancy  
   **Severity**: Medium  
   **Affected Function**: `emergencyWithdraw` (line 28)  
   **Description**: The `emergencyWithdraw` function uses `call{value: ...}("")` to transfer funds to the `treasury` address. If the `treasury` is a contract with a fallback function that re-enters this contract before the initial call completes, it could potentially drain funds again. While the function does not modify state before the transfer, the lack of a reentrancy guard introduces a risk if the `treasury` is malicious.  
   **Recommended Fix**: Add a reentrancy guard (e.g., `ReentrancyGuard` from OpenZeppelin) or ensure the `treasury` is an externally owned account (EOA) to prevent reentrancy attacks.

2. **Vulnerability Type**: Access Control  
   **Severity**: Medium  
   **Affected Function**: `setTreasury` (line 19)  
   **Description**: The `setTreasury` function allows the owner to update the `treasury` address. If the owner is compromised, an attacker could redirect all funds to a malicious contract. While the function itself is properly restricted to the owner, the lack of additional safeguards (e.g., multi-sig approval) increases risk.  
   **Recommended Fix**: Implement multi-sig or timelock mechanisms for critical state changes like updating the `treasury`.

3. **Vulnerability Type**: Unprotected Funds  
   **Severity**: Medium  
   **Affected Function**: `deposit` (line 15)  
   **Description**: The `deposit` function allows anyone to send ETH to the contract, but there is no mechanism for non-owners to withdraw funds except `emergencyWithdraw` (which is owner-only). This creates a risk of funds being locked if the owner becomes unresponsive or malicious.  
   **Recommended Fix**: Add a withdrawal mechanism for users or ensure the owner is trusted and has a contingency plan for unresponsiveness.

### Overall Security Score: **8/10**
