   **Severity**: Medium

   **Description**: The contract does not validate that the `s` value in the ECDSA signature is within the valid range (`s <= secp256k1n / 2`). This allows for signature malleability, where an attacker could generate a different valid signature for the same message. While the `usedSigs` mapping prevents replay attacks for the same `(to, amount)` combination, the lack of `s` validation could lead to ambiguity in signature verification.  
   **Fix**: Add a check to ensure `s <= 0x7FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF5D576E7357A4501DDFE92F46681B20A0` (half of the secp256k1 curve order) in the `_recover` function.
